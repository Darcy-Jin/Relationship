# AI 漫画内容地图 v0.1

> 状态：Current / Planning  
> 作用：定义 Relationship AI Comic 的内容空间，回答“以后可以从哪些人物、生活和需要组合出内容”。  
> 它不替代 [内容模型](content-model.md)。内容模型负责“一篇怎么生成、怎么组成”；本文件负责“有哪些值得组合的内容材料”。

## 1. 先记住一个公式

~~~text
人物 / 标签 / 特点
×
生活场景 / 人生阶段
×
伴侣需要 / 生活方式
↓
形成一个 Topic Candidate
↓
再进入 Content Model
~~~

这里不是把三个列表机械做笛卡尔积。

真正要找的是：

> **某个具体的人身上的一个特点，进入某段真实生活以后，对不同需要的人会产生明显不同的体验。**

只有这种组合，才值得继续变成一篇内容。

---

# 2. 维度一｜人物 / 标签 / 特点

这一维回答：

> **这一篇主要在看这个人身上的什么？**

标签只是内容入口，不是人物结论。正式人物模型继续读取：

- [人物模型 v0.1](../../models/person-model.md)

为了内容规划，先把入口分成七类。

## 2.1 现实条件与资源

回答：

> 他现在客观拥有什么、处在什么位置？

例如：

- 年龄；
- 城市；
- 学历；
- 职业；
- 收入；
- 房产 / 住房；
- 家庭条件；
- 外貌与身体条件。

这类最容易成为相亲和择偶中的第一眼标签。

但内容必须继续追问：

> **这个条件最后怎样影响生活，而不是条件本身高低。**

## 2.2 相对稳定的倾向

回答：

> 他通常更容易怎样反应？

例如：

- 外向 / 内向；
- 谨慎 / 冒险；
- 敏感 / 钝感；
- 控制感强 / 随和；
- 自律 / 随性；
- 开放 / 保守。

这类不能直接推出行为，必须进入场景验证。

## 2.3 价值、目标与人生优先级

回答：

> 他真正把什么排在前面？

例如：

- 事业；
- 家庭；
- 钱；
- 自由；
- 稳定；
- 成长；
- 是否要孩子；
- 对忠诚、责任、家庭的理解。

这类往往决定长期生活方向。

## 2.4 能力与长期训练

回答：

> 他实际能把什么事情做好？

例如：

- 赚钱能力；
- 决策能力；
- 沟通能力；
- 情绪调节；
- 家务和生活管理；
- 学习和修正能力；
- 处理复杂问题的能力。

能力和性格不是一回事。

一个人天然不擅长某件事，也可能经过长期训练形成很强能力。

## 2.5 生活习惯与资源分配方式

回答：

> 他平时把时间、钱、精力和注意力用在哪里？

例如：

- 工作投入；
- 作息；
- 消费 / 储蓄；
- 健身；
- 社交；
- 游戏 / 兴趣；
- 整洁；
- 旅行；
- 陪伴家人。

这一类通常最容易直接变成共同生活。

## 2.6 经历与当前现实状态

回答：

> 什么经历塑造了他，以及他现在正在经历什么？

例如：

- 原生家庭；
- 过去的恋爱 / 婚姻；
- 创业；
- 失业；
- 债务；
- 父母生病；
- 带孩子；
- 长期高压工作；
- 一段重大成功或失败。

这里尤其要避免把经历直接变成人格结论。

## 2.7 在关系中的行为方式

回答：

> 他进入关系以后，通常怎样回应和处理事情？

例如：

- 会不会回应；
- 关键时刻是否可靠；
- 冲突时表达还是回避；
- 是否尊重边界；
- 愿不愿意修复；
- 是否习惯控制、迁就或冷处理。

这一类和“关系过程”高度相关。

它可以作为内容入口，但不能假设是脱离伴侣和场景的永久标签。

### 这一维当前的结构

~~~text
人物 / 标签 / 特点
├─ 现实条件与资源
├─ 稳定倾向
├─ 价值 / 目标 / 优先级
├─ 能力与训练
├─ 生活习惯 / 资源分配
├─ 经历 / 当前状态
└─ 关系中的行为方式
~~~

# 3. 维度二｜生活场景

这一维回答：

> **这个特点到底放进哪一段真实生活里看？**

“场景”不是一张扁平清单。

更准确是三个坐标共同决定：

~~~text
人生 / 关系阶段
×
共同生活领域
×
具体事件 / 压力 / 约束
=
一个可画出来的真实场景
~~~

## 3.1 人生 / 关系阶段

先回答：

> 现在两个人走到哪一步了？

当前第一层：

~~~text
认识 / 相亲
↓
恋爱
↓
异地 / 磨合
↓
同居 / 婚前
↓
结婚 / 建立家庭
↓
备孕 / 怀孕 / 生育
↓
婴幼儿照护
↓
孩子成长 / 教育
↓
中年：事业 + 孩子 + 父母
↓
老年 / 长期照护 / 退休
~~~

不是每篇都要覆盖完整时间线。

时间线的作用是：

> **让同一个特点在不同阶段重新接受生活检验。**

## 3.2 共同生活领域

再回答：

> 这一段生活具体在处理什么事情？

沿用 Relationship 当前正式领域：

- 日常作息；
- 工作与事业；
- 钱与消费；
- 房与居住；
- 家务；
- 孩子；
- 双方父母；
- 社交；
- 兴趣与休闲；
- 个人空间；
- 性与亲密；
- 健康；
- 地点 / 搬家 / 迁移；
- 价值与人生方向。

## 3.3 事件、压力与变化

最后回答：

> 有什么事情让原来的生活结构发生变化？

例如：

- 加班 / 晋升；
- 失业 / 创业；
- 收入突然变化；
- 买房 / 装修；
- 怀孕 / 生孩子；
- 孩子生病 / 入学；
- 父母住院；
- 搬家 / 异地；
- 自己生病；
- 经济压力；
- 一方需要长期照护。

重大事件不是为了制造狗血。

它真正的价值是：

> **让平时不容易看见的人物模式和关系运行方式显现出来。**

### 一个场景的例子

~~~text
育儿期
×
工作
×
临时加班
↓
孩子突然发烧，但一方今晚必须处理工作事故
~~~

这才是可以进入漫画的场景。

# 4. 维度三｜伴侣需要 / 生活方式

这一维回答：

> **为什么同一个人、同一件事，对不同人意义完全不同？**

这里不是给用户再做一套人格标签。

它描述的是：

> **我在一段共同生活里真正需要什么、能承受什么、愿意交换什么。**

当前先分成六组。

## 4.1 亲密与连接

包括：

- 需要多少陪伴；
- 需要多少共同活动；
- 需要多少情绪交流；
- 是否重视浪漫和仪式；
- 对性与身体亲密的需要。

## 4.2 自主、空间与生活节奏

包括：

- 需要多少个人空间；
- 是否喜欢各忙各的；
- 社交频率；
- 作息节奏；
- 计划性与随性；
- 是否需要大量独处。

## 4.3 安全、稳定与资源

包括：

- 对收入和财务安全的需要；
- 对住房和生活稳定性的需要；
- 对风险的承受度；
- 对可预测生活的需要。

## 4.4 责任、可靠与合作

包括：

- 关键时刻是否出现；
- 家务 / 育儿 / 照护怎样分；
- 是否在意公平；
- 承诺后是否执行；
- 遇到问题愿不愿意一起扛。

## 4.5 成长、事业与未来方向

包括：

- 事业投入程度；
- 是否支持彼此成长；
- 是否要孩子；
- 城市 / 迁移选择；
- 希望过什么样的人生。

## 4.6 边界与家庭关系

包括：

- 双方父母介入到什么程度；
- 钱、时间和隐私的边界；
- 朋友与异性交往边界；
- 家庭融合程度；
- 哪些事情不能交换。

### 这一维最重要的不是“类型”

同一个人可以同时：

- 很需要情绪连接；
- 又需要大量独处；
- 对钱要求普通；
- 但对可靠性要求极高。

所以不要把用户压成“独立型”“陪伴型”几个固定人设。

真正要表达的是：

> **不同需要组合，会让同一种生活产生不同体验。**

# 5. 三个维度怎么真正组合成内容

不是看到一个标签就开始写。

先完成：

~~~text
人物入口
↓
这个特点为什么有人会喜欢 / 在意
↓
把它放进一个具体生活场景
↓
看见真实收益
↓
看见资源投入 / 限制 / 机会成本
↓
换一种伴侣需要重新看
↓
判断这里有没有真正的生活张力
~~~

如果有，才形成 Topic Candidate。

## 5.1 例子一｜事业心强

~~~text
人物特点
→ 事业心强 / 工作投入高

生活场景
→ 生孩子以后，孩子晚上发烧

伴侣需要
→ 需要关键时刻可靠

真正的问题
→ 我能接受你平时工作很忙，但真正需要你的时候，你能不能出现？
~~~

重点已经不是：

> 事业心强到底好不好。

而是：

> **什么样的事业投入方式，可以和我需要的可靠性一起存在？**

## 5.2 例子二｜很节俭

~~~text
人物特点
→ 节俭 / 储蓄倾向高

生活场景
→ 同居以后日常消费 + 一年一次旅行

伴侣需要
→ 财务安全 + 也希望有生活体验

真正的问题
→ 省钱给我安全感，但如果所有享受都被否掉，我能接受吗？
~~~

## 5.3 例子三｜很会社交

~~~text
人物特点
→ 社交能力强 / 朋友很多

生活场景
→ 婚后周末安排

伴侣需要
→ 一方喜欢热闹，一方需要大量两人时间

真正的问题
→ 我喜欢他的社交能力，但我想要的周末到底是什么样？
~~~

# 6. Topic Candidate Gate

不是所有组合都值得做成内容。

进入 Content Brief 前至少检查：

1. **人物入口是否一眼能懂？**
2. **这个特点为什么会让人想要 / 在意？**
3. **有没有一个能画出来的具体生活场景？**
4. **有没有真实收益，而不是只为了批判这个人？**
5. **有没有真实限制 / 代价 / 机会成本？**
6. **换一种伴侣需要以后，判断会不会发生有意义的变化？**
7. **有没有把概率、倾向或条件写成必然？**
8. **这个问题最终会不会帮助读者更清楚自己想过什么生活？**

至少前 6 条说不清时，不急着进入脚本。

# 7. 和 Content Model 的关系

本文件负责：

~~~text
内容空间
↓
人物 / 特点
×
生活场景
×
伴侣需要
↓
Topic Candidate
~~~

[内容模型](content-model.md) 接着负责：

~~~text
Topic Candidate
↓
Content Brief
↓
标题
↓
若干基本内容单元
↓
整篇收口
~~~

两个文件不要互相复制。

---

# 8. 当前还不做什么

当前不：

- 把三个维度全部展开成几百个组合；
- 为每个组合提前写标题；
- 把所有标签都当成稳定人物类型；
- 为了完整建立巨型人物分类学；
- 因为 Character Style 未完成而停止内容规划。

当前先验证：

> **这三个维度是否足以稳定地产生 Relationship 真正想做的内容。**

验证以后，再逐层扩人物标签库、生活场景库和 Topic Pool。
