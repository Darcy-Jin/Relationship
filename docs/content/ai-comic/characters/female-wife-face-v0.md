## 3. 目前已经确认的“现在的她”

### 3.1 头脸整体

当前照片里稳定看到的是：

- 头脸视觉上偏小、紧凑；
- 整体偏窄长的椭圆感；
- 不是宽圆脸；
- 也不是 V 脸；
- 头顶轮廓圆润，不是尖顶；
- 五官在整张脸上显得相对集中。

当前先把“视觉上小而紧凑”作为生成规则。

> **真实物理头围是否显著小于普通人，尚未测量，不作为硬结论。**

### 3.2 五官位置

重点不是把单个五官画漂亮，而是保持它们在这张脸上的关系：

- 眼、鼻、嘴相对集中；
- 不因为脸偏长，就把五官上下拉散；
- 眼睛不要自动放大；
- 鼻子保持自然比例；
- 嘴不能缩得太小。

这组“相对集中”的关系，是目前本人识别度的重要部分。

### 3.3 颧骨、苹果肌和中脸

- 颧骨有存在感；
- 鼻子两侧、眼下、颧骨前方的苹果肌有体积；
- 面中不是平板；
- 3/4 角度时，中脸前向体积也必须保留；
- 不能为了柔和或美化，把颧骨和苹果肌磨平。

### 3.4 下颌、下巴和下颊软组织

这是当前最容易画错的地方。

正确关系是：

- 下颌转折柔和；
- 从下颊到下巴是缓慢连续地收；
- 下巴末端圆润，不是一个尖点；
- 下巴不能收得过窄；
- 颧骨下方、下颊前段、下巴两侧保留一点软组织；
- 这种局部软组织不能被误画成整张脸变宽、变胖。

一句话：

> **外轮廓偏窄长，但下半脸里面是软的。**

## 4. 眼睛：现在是双眼皮，但眼神不能“太有神”

当前按现在照片处理：

- 现在是双眼皮；
- 眼型自然，不夸大；
- 眼睛纵向开合偏克制；
- 上眼睑比较放松；
- 下方眼白露得少；
- 眼尾和下眼睑线条偏柔；
- 虹膜 / 眼白反差不要太硬；
- 不使用大而亮的高光点强化“闪亮眼”。

用户描述的“朦胧感”，当前翻译为：

> **有焦点，但不锐；清醒，但柔；眼神松、软、略带雾感。**

不是：

- 失焦；
- 困；
- 无神；
- 瞳孔模糊。

## 5. 表情：她不是标准甜笑

### 5.1 习惯性微笑 / “假笑感”

她有一种很有本人辨识度的微笑：

- 嘴角更多是向两侧拉，再轻微往上；
- 有一点抿住 / 努住的感觉；
- 两边不一定完全对称；
- 口周会稍微有一点紧；
- 所以笑容会有一点僵；
- 眼睛不一定同步变成夸张笑眼；
- 整体有一点古灵精怪、有主意、小机灵的感觉。

这不是生成缺陷。

> **不要把这种略僵、努嘴角的本人笑，自动优化成标准甜美笑。**

### 5.2 真正开心时

真正开心时才明显出现：

- 颧骨上提；
- 苹果肌变饱满；
- 下眼睑和眼尾参与；
- 眼睛自然变窄；
- 面中整体被带起来。

### 5.3 表情会改变下巴观感，但不能改变骨相

努嘴角、轻侧转时，下巴可能在照片里显得更尖。

这是：

> **表情 + 角度造成的视觉变化**

不是：

> **她本来就是尖下巴。**

静态结构仍然按：

> **圆下巴 + 柔和下颌 + 下颊软组织**

处理。

## 6. 3/4 与侧脸

侧过去以后也必须还是同一张脸。

必须保留：

- 颧骨高点；
- 眼下—颧骨前方的体积；
- 苹果肌；
- 颧骨下方少量软组织；
- 下颊到下颌前段的肉感；
- 柔和下颌；
- 圆润、不过窄的下巴。

禁止把 3/4 / 侧脸自动变成：

> **削骨感 + 平中脸 + 干净下颌线 + 尖下巴**

那会从“她”滑成标准美型脸。

### 6.1 跨视角不是各画各的

正脸、3/4、侧脸都来自同一个潜在三维结构。

当前不要求：

> 从一张正脸精确计算出唯一侧脸。

但要求：

> **不同视角之间的结构不能互相冲突。**

本人物当前已确认的高层跨视角约束：

- 整体头脸包络偏柔和，不是尖锐 V 型；
- 中脸不是干瘪平板；
- 下颊存在轻微软组织缓冲；
- jaw → chin 是连续缓慢收束；
- chin tip 偏圆钝、不过窄；
- 整体观感偏柔和、圆润、可爱，而不是硬、利、尖。

所以纯侧脸如果突然出现：

- 下颌快速收成尖点；
- 中脸明显更硬；
- 下颊缓冲消失；
- 整体从柔和变成锐利；

即使这张侧脸单独“合理”，也不能直接认为它属于本人。

必须同时通过：

> **Cross-view Structural Consistency｜跨视角结构一致性。**

## 7. 胖瘦：下一阶段再调

当前先按现在照片里的自然状态画：

- 不主动瘦脸；
- 不主动增胖；
- 不做更年轻；
- 不做更精致。

只有用户先确认：

> **“这张脸基本就是她。”**

以后才允许微调：

- 稍瘦一点；
- 稍丰满一点；
- 苹果肌多一点 / 少一点；
- 下颊软组织多一点 / 少一点。

原则：

> **胖瘦是状态变量，不能用胖瘦去修一个还没画对的身份。**

## 8. 当前仍属于“假设”，不要写成硬规则

下面这些目前只能作为辅助判断：

- 她的真实物理头围是否明显比普通人小；
- “小头”到底对可爱感贡献多大；
- 之前粗测的头高 / 头宽约 1.35～1.40；
- 眼线到嘴线约占头高 30～32%；
- “可爱感”是否主要来自某一组固定比例。

这些可以帮助分析，但：

> **不能要求生成模型机械按数字画。**

最终仍以真人照片和人工“像不像”的判断为准。

### 9.1 Root Master

**Root Master｜正脸自然**

- 浅蓝 T 恤；
- 正脸；
- 自然 / 中性表情；
- 无眼镜；
- 灰色中性背景；

用途：

### 9.2 Support Masters

**Support｜正脸轻微微笑**

- 用于验证轻微表情变化时身份是否稳定。

**Support｜正脸说话状态**

- 用于验证张嘴 / 说话时嘴部与下半脸不会换型。

**Support｜正脸露齿笑**

- 用于验证更明显笑容下的动态身份。

**Support｜轻 3/4**

- 用于验证轻侧转时颧骨、中脸、下颌和下巴仍然是同一个人。

**Support｜戴眼镜轻 3/4**

- 眼镜只作为 Appearance State；
- 继续由 Root Master 提供 Identity Core；
- 不允许“戴眼镜”重新定义成一张知性模板脸。

### 9.3 当前 Master 的使用原则

以后优先：

~~~text
Root Master
├─ 发型变体
├─ 胖瘦变体
├─ 穿搭 / 职业
├─ 场景
└─ 画风
~~~

必要时带 1 张 Support Master 补角度 / 表情 / 眼镜。

不要默认：

~~~text
Root → 未验证 A → 未验证 B → 未验证 C
~~~

只有中间结果通过：

- Identity Fidelity；
- Target Change Fidelity；
- Non-target Preservation；

才可以升级成 Validated Branch Master。

### 9.4 已确认失败样本

随后重新生成的多格合集出现：

- 脸变尖；
- 嘴角 / 酒窝感异常；
- 第一排即不像。

该合集不进入 Master Bank。

当前已确认原因：

> **为了做合集又重新生成全部人物，导致已经确认的身份被再次合成。**

以后合集 / 对比板只允许确定性排版，不重新生成已确认人物。

它的用途是提醒后续生成不要丢掉：

- 小而紧凑的头脸感；
- 窄长椭圆；
- 五官集中；
- 圆润下巴；
- 下巴两侧软组织；
- 温柔、可爱、灵动，而不是尖锐、美型。

它不是原图，也不是最终 Master。
