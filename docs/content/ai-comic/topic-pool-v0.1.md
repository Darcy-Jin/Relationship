# AI 漫画 Topic Pool v0.1｜内容地图验证样本

> 状态：Validation Sample  
> 作用：用少量不同类型的真实候选题验证 [内容地图 v0.1](content-map-v0.1.md) 是否够用。  
> 这不是正式发布排期，也不是一次性选题大全。

## 1. 验证目的

当前要验证：

~~~text
人物 / 标签 / 特点
×
生活场景
  = 人生阶段 × 共同生活领域 × 事件 / 压力
×
伴侣需要 / 生活方式
↓
是否能稳定形成一个值得讲的真实生活问题
~~~

如果一个候选题必须不断增加新维度才能说清，说明 Content Map 还不够。

---

## 2. Candidate 001｜互联网大厂男友：高薪，但没时间

~~~text
人物特点
→ 高收入 + 高事业投入 + 时间少

生活场景
→ 恋爱 / 同居 × 日常作息 / 共同时间 × 加班

伴侣需要
→ 高陪伴需求 vs 高独立需求

真正问题
→ 这种高收入、低共同时间的生活，我到底喜不喜欢？
~~~

状态：已有 Episode 001，用作基准样本。

---

## 3. Candidate 002｜事业心强：平时忙没关系，关键时候呢？

~~~text
人物特点
→ 事业心强 / 工作责任高

生活场景
→ 育儿期 × 工作 / 孩子 × 孩子突然生病 + 工作事故

伴侣需要
→ 平时可以各忙各的，但关键时刻必须可靠

真正问题
→ 我介意的是你忙，还是我真正需要你的时候你仍然把工作排第一？
~~~

可用内容单元：

- 平时高投入工作带来的收入 / 成长；
- 孩子突然生病时谁离开工作；
- 不同家庭分工下，同一件事的意义如何变化。

---

## 4. Candidate 003｜很节俭：省下来的钱，让我安心还是让我憋屈？

~~~text
人物特点
→ 节俭 / 储蓄倾向高

生活场景
→ 同居 / 婚后 × 钱 / 休闲 × 日常消费 + 旅行

伴侣需要
→ 财务安全 vs 生活体验

真正问题
→ 我想要的是会存钱的人，还是一种我也能接受的花钱方式？
~~~

可用内容单元：

- 日常不乱花；
- 旅行、餐厅、兴趣也不断被压缩；
- 如果两个人都重视长期安全，体验可能完全不同。

---

## 5. Candidate 004｜很顾家：他顾的是“小家”，还是整个大家庭？

~~~text
人物特点
→ 顾家 / 重家庭

生活场景
→ 婚后 × 双方父母 / 时间 / 钱 × 父母频繁需要帮助

伴侣需要
→ 家庭融入 vs 夫妻边界

真正问题
→ 我喜欢他有家庭责任感，但这个“家”到底包括谁，边界在哪里？
~~~

可用内容单元：

- 主动承担家庭事务的好处；
- 时间、钱和决定权大量流向原生家庭；
- 如果自己也希望两边家庭高度融合，意义会变化。

---

## 6. Candidate 005｜朋友很多的男朋友：热闹，还是永远排不到我？

~~~text
人物特点
→ 社交能力强 / 朋友多 / 活动多

生活场景
→ 恋爱 / 婚后 × 社交 / 周末 / 共同时间 × 聚会安排

伴侣需要
→ 热闹社交 vs 两人时间 / 安静生活

真正问题
→ 我喜欢的是他的社交能力，还是我也真的喜欢这种周末？
~~~

可用内容单元：

- 朋友多、资源多、活动丰富；
- 周末和晚上经常已有安排；
- 对本身也爱社交的人，这可能恰好是共同生活。

---

## 7. Candidate 006｜情绪很稳定的人：冷静，还是你难受时他只会讲道理？

~~~text
人物特点
→ 情绪稳定 / 理性 / 不容易失控

生活场景
→ 恋爱 / 婚后 × 冲突 / 健康 × 一方情绪低落或生病

伴侣需要
→ 解决问题 vs 被理解 / 被回应

真正问题
→ 我需要的是一个不会失控的人，还是一个在我难受时知道怎么回应我的人？
~~~

注意：

> 情绪稳定不等于缺乏共情。内容必须写具体行为，不能把两个概念强行绑定。

---

## 8. Candidate 007｜从来不跟你吵架的人：好脾气，还是很多话根本没说？

~~~text
人物特点
→ 随和 / 不爱冲突 / 很少吵架

生活场景
→ 长期恋爱 / 婚后 × 家务 / 钱 / 冲突 × 同一问题重复出现

伴侣需要
→ 表面和谐 vs 真实表达 / 修复

真正问题
→ 我真正想要的是“不吵架”，还是问题出现以后两个人能处理掉？
~~~

可用内容单元：

- 小事上很好说话；
- 真正不同意时也不说；
- 对双方本来差异很少、且能主动沟通的人，少冲突未必是问题。

---

## 9. Candidate 008｜很独立的伴侣：给你自由，也可能不太需要你

~~~text
人物特点
→ 独立 / 自我完成度高 / 很少依赖别人

生活场景
→ 恋爱 / 生病 / 压力期 × 个人空间 / 照护 × 一方真正需要支持

伴侣需要
→ 自主空间 vs 相互依赖 / 被需要感

真正问题
→ 我喜欢彼此不束缚，但我希望关系里保留多少“可以依靠彼此”？
~~~

注意：

> 独立不等于冷漠。要把“很少求助 / 很少介入 / 很能自己处理”拆成具体行为。

---

## 10. Candidate 009｜特别自律的人：你喜欢的是他的状态，还是他的生活方式？

~~~text
人物特点
→ 自律 / 健身 / 饮食管理 / 作息规律

生活场景
→ 同居 / 育儿 × 作息 / 健康 / 休闲 × 每周固定训练和饮食安排

伴侣需要
→ 共同健康生活 vs 自由随性 / 大量共同时间

真正问题
→ 我喜欢他的身材和状态，但我愿不愿意一起过支撑这种状态的日子？
~~~

可用内容单元：

- 好身材 / 精神状态；
- 规律训练、早睡、饮食控制；
- 如果自己也喜欢这种生活，它会从“代价”变成共同活动。

# 11. 第一轮验证结果

这 9 个题覆盖了：

- 现实资源：高收入；
- 价值 / 优先级：事业、家庭；
- 生活习惯 / 资源分配：社交、节俭、自律；
- 稳定倾向：理性、独立、随和；
- 关系行为：可靠、表达、回应；
- 恋爱、同居、婚后、育儿；
- 钱、工作、父母、社交、冲突、健康、作息；
- 陪伴、空间、安全、回应、可靠、公平、边界、生活节奏等不同需要。

当前没有发现必须新增第四个平级维度才能说清的候选题。

因此 v0.1 暂时保留：

~~~text
人物 / 特点
×
生活场景
×
伴侣需要
~~~

但有两个重要约束：

### 11.1 “关系过程”不是第四维

回应、可靠、公平、边界、冲突、修复会出现在很多内容里。

它们有时是：

- 人物行为入口；
- 场景中真正暴露的问题；
- 伴侣真正需要的东西。

所以先作为跨维机制使用，不单独再开一条内容线。

### 11.2 “时间”不是第四维

时间已经进入：

> **生活场景的人生 / 关系阶段。**

同一个特点在恋爱、同居、育儿、中年会呈现不同意义。

因此不再把“时间”单独做一条内容赛道。

---

# 12. 下一步

第一轮验证后，下一步不再继续增加模型层。

开始逐层建设三个可复用资产：

~~~text
A. 人物 / 标签 / 特点库
B. 生活场景库
C. 伴侣需要 / 生活方式库
~~~

优先先做 A：

> **用户现实中会拿什么词来形容 / 筛选一个对象，以及这些词应该怎样从标签继续落到可观察的生活特点。**

完成 A 的第一层后，再和 B / C 组合形成第一批正式 Topic Pool。
