# Need / Fit Space 候选模型 v0.1

> 状态：Research-only / Candidate Model  
> 上游 Raw Corpus：`raw-corpus-v0.1.csv`  
> Mapping：`raw-to-view-mapping-v0.1.csv`

## 1. Need / Fit 不是一张“我想要什么”清单

第一轮 212 条 Raw Item 显示，至少要分开六个问题：

~~~text
我需要什么？
↓
这个需要是什么形状？
↓
现实里什么行为 / 关系过程会满足或破坏它？
↓
两个人的差异怎样形成 Fit？
↓
我愿意拿什么换什么？
↓
哪些东西根本不进入交换？
~~~

因此当前保留 6 个 Need / Fit View。

# 2. N1｜Need Content

回答：

> **我在长期共同生活里真正需要什么？**

当前第一层 12 组：

~~~text
N1.1 吸引 / 欲望
N1.2 陪伴 / 连接 / 归属
N1.3 被理解 / 被回应 / 被关心
N1.4 自主 / 空间 / 自由
N1.5 安全 / 信任 / 可预测
N1.6 经济 / 物质安全
N1.7 公平 / 可靠 / 合作
N1.8 成长 / 能力 / 目标支持
N1.9 活力 / 新鲜感 / 有趣 / 共同体验
N1.10 性 / 身体亲密
N1.11 家庭投入 / 家庭边界
N1.12 价值 / 人生方向 / 未来一致性
~~~

这些组不是永久 taxonomy，而是当前覆盖足够广的认知 View。

### N1.1 吸引 / 欲望

继续区分：

- 大众外在吸引；
- 我个人是否顺眼；
- 生理性吸引；
- 相处后形成的关系性吸引。

所以“颜值高”不等于“我想和他亲密”。

### N1.2 陪伴 / 连接

可能包括：

- 日常共同时间；
- 一起做事；
- 情绪连接；
- 归属；
- 关系中的存在感。

它不等于 24 小时黏在一起。

### N1.3 被理解 / 被回应

外部 responsiveness 研究通常把它拆成：

- understood；
- validated；
- cared for。

对 Relationship 来说，它意味着：

> **我说出重要的东西以后，对方有没有真的接住。**

### N1.4 自主 / 空间

SDT 提醒：

> 自主不等于疏离，也不等于完全不依赖。

一个人可以很亲密，同时仍然需要：

- 自己决定；
- 自己的时间；
- 自己的兴趣；
- 不被控制。

### N1.5 安全 / 信任 / 可预测

包括：

- 不被抛弃的安全；
- 承诺稳定；
- 行程 / 生活可预测；
- 不用长期猜对方在想什么；
- 对风险的共同承受。

### N1.6 经济 / 物质安全

重点不是“越有钱越好”，而是：

- 能不能维持基本生活；
- 对风险的承受；
- 财务是否透明；
- 目标是否能协调；
- 钱是否持续制造不安全。

### N1.7 公平 / 可靠 / 合作

包括：

- 说到做到；
- 关键时刻出现；
- 家务 / 育儿 / 照护能合作；
- 分工让双方觉得合理；
- 不把共同责任默认推给另一方。

### N1.8 成长 / 目标支持

包括：

- 伴侣支持我的事业 / 学习；
- 不压制我变好；
- 能提供实际或情绪支持；
- 两个人可以共同成长，也可以分别成长。

### N1.9 活力 / 新鲜感 / 有趣

包括：

- 社交活力；
- 探索；
- 幽默；
- 旅行；
- 新体验；
- 共同活动。

### N1.10 性 / 身体亲密

包括：

- 性吸引；
- 性需求；
- 身体接触；
- 性沟通；
- 自主与同意；
- 忠诚边界。

### N1.11 家庭投入 / 家庭边界

包括：

- 是否愿意建立和投入小家庭；
- 是否愿意承担育儿 / 照护；
- 双方父母的边界；
- 钱、时间和居住怎样分配。

### N1.12 价值 / 未来方向

包括：

- 是否要孩子；
- 事业 / 家庭排序；
- 城市；
- 婚姻意义；
- 对忠诚、自由、成功的理解；
- 长期人生目标。

# 3. N2｜Need Shape / Preference Function

回答：

> **这个需要到底怎样影响选择？**

当前正式沿用 Relationship 已有六种形状：

~~~text
N2.1 门槛 / Gate
N2.2 越高越好但会逐渐够用
N2.3 最舒服区间
N2.4 两人组合 / Fit
N2.5 条件性接受
N2.6 可承受代价 / Trade-off
~~~

另外：

> **Safety Boundary 不属于普通 Preference Shape，单独进入 N6。**

同一个 Need 对不同人可以有不同形状。

例如陪伴：

- 有人有最低门槛；
- 有人存在舒服区间；
- 有人只要求“关键时刻出现”；
- 有人愿意为了高自主交换日常陪伴。

所以不能统一做成 1～10 权重。

# 4. N3｜Fulfillment / Relationship Mechanism

回答：

> **什么现实过程让一个需要真的被满足或破坏？**

当前第一层：

~~~text
N3.1 回应 / 理解 / 验证 / 关心
N3.2 可靠 / 承诺执行
N3.3 公平 / 共同承担
N3.4 自主支持 / 尊重选择
N3.5 情绪 / 实际支持
N3.6 沟通 / 自我披露
N3.7 冲突 / 修复
N3.8 共同应对压力
N3.9 目标支持
N3.10 性沟通 / 性自主支持
~~~

这层特别重要，因为：

> **“我需要什么”不能直接推出“对方应该具有什么标签”。**

例如：

~~~text
Need
→ 被理解

Fulfillment Mechanism
→ 我表达以后，对方准确理解、承认我的感受并愿意调整

不是
→ 找一个“情商高”的人
~~~

# 5. N4｜Fit Mode / Coordination

回答：

> **两个人怎样组合，才让同一个特点变得舒服或难受？**

当前第一层：

~~~text
N4.1 相似
N4.2 互补
N4.3 差异但互不干扰
N4.4 差异需要协调
N4.5 条件性兼容
N4.6 核心方向冲突
~~~

重要修正：

> **Compatibility ≠ Similarity。**

研究显示某些目标、价值或人格相似与关系结果存在小幅关联，但整体相似并不是万能解释；个体自身特点和具体互动常常更重要。

所以 Relationship 不做：

> “越像越配。”

而是继续问：

> **这个差异进入生活以后要不要协调，能不能协调，协调成本多大。**

---

# 6. N5｜Trade-off / Tolerance

回答：

> **为了真正重要的东西，我愿意承受什么不完美？**

当前至少分：

~~~text
N5.1 喜欢
N5.2 能接受
N5.3 必须调整
N5.4 长期不能接受
N5.5 愿意交换
N5.6 改变条件以后可以接受
~~~

真正的内容价值通常发生在这里。

例如：

~~~text
我喜欢事业心强
+
我能接受平时陪伴少
+
但我不能接受关键时刻仍然不出现
~~~

这比“事业型适不适合结婚”准确得多。

---

# 7. N6｜Safety / Non-compensable Boundary

回答：

> **哪些问题不能用其他优点换回来？**

当前正式安全边界继续包括：

- 身体暴力；
- 性胁迫；
- 强制控制；
- 严重心理虐待；
- 跟踪；
- 威胁；
- 严重经济控制。

这层不进入普通 Trade-off。

---

# 8. Need / Process / State 必须分开

最容易混淆的三个东西：

~~~text
Need
= 我需要什么

Relationship Process
= 两个人怎么互动

Relationship State
= 互动以后现在变成什么状态
~~~

例如：

~~~text
Need
→ 安全感

Process
→ 承诺执行 + 透明沟通 + 边界尊重

State
→ 信任 / 安全上升或下降
~~~

不再把三者都写成一个“安全感标签”。

---

# 9. 一个 Need / Fit 的运行链

~~~text
Need Content
↓
Need Shape
↓
进入一个具体 Scene
↓
对方 / 双方通过某种 Relationship Process 行动
↓
Need Fulfilled / Thwarted
↓
形成主观体验和 Relationship State
↓
玩家判断是否喜欢 / 接受 / 必须改变 / 不能继续
↓
多个场景以后形成当前 Trade-off / Fit 认识
~~~

这条链同时能服务 AI Comic 和 Relationship Game。

# 10. 当前用法

内容生产时不直接从 N1 列表抽一个词写文章。

而是：

~~~text
Person Feature
×
Scene
×
Need Content + Need Shape
↓

↓
形成 Fit / Trade-off
↓
Topic
~~~
