## 2. 第一轮结论

### 2.1 原来的“阶段 × 领域 × 事件”是对的，但还不够

它能回答：

- 什么时候；
- 在生活哪一块；
- 发生什么变化。

但要变成真正可画、可用于判断的内容，还需要补两层：

> **任务 / 资源怎么重新分配**

以及：

> **现场到底需要怎么行动 / 协商。**

所以 Scene Space 从原来的三坐标扩为：

~~~text
Stage
× Domain
× Trigger
× Task / Resource Reallocation
→ Concrete Scene
→ Decision / Interaction
+ Pattern over Time
~~~

这不是给内容增加复杂度，而是把后台研究做完整；单篇仍只拿需要的部分。

### 2.2 时间不仅是 Life Stage

原来我们把“时间”主要放进人生阶段。

Raw Corpus 说明还需要另一种时间：

- 第一次；
- 第三次；
- 每周；
- 持续半年；
- 已经说过很多次；
- 调整以后有没有维持。

因此：

> **Life Stage 和 Pattern / Repetition 是两个不同的 Time View。**

它们不能合并成一个“时间维度”。

### 2.3 压力事件的价值不是狗血，而是暴露机制

生育、失业、慢性病、父母住院、工作冲突等研究都显示，这些变化会重新配置角色、时间、劳动、照护和沟通。

所以内容里的压力事件应该服务：

> **让平时不容易看见的人物模式和关系过程显现。**

而不是为了制造冲突而冲突。

### 2.4 中国 Context 需要保留“双方父母 / 同住 / 亲属支持”

中国研究里，夫妻关系与父母 / 姻亲关系、亲属支持、共同居住、家务和育儿安排有独立现实意义。

因此父母不能只作为一个普通 Event Domain。

后续 Scene Library 需要能区分：

- 父母提供资源；
- 父母提供照护；
- 父母需要照护；
- 父母介入决策；
- 同住 / 近住 / 分开住。

# 3. 当前来源偏差

## 3.1 Domain / Scene 很多，Pattern Dynamics 太少

S7 只有 7 个直接 Raw Item。

这说明现有资料擅长告诉我们：

> “会发生哪些事情”

但较少系统记录：

> “它怎样反复、累积、修复或恶化”。

后续要从纵向关系研究、游戏运行和真实案例中继续补。

## 3.2 当前 Scene Corpus 偏异性伴侣 / 婚育路线

现有家庭研究和 Relationship 当前产品都更偏：

- 异性伴侣；
- 结婚；
- 生育；
- 共同居住。

正式产品未来扩性别 / 关系形式时，需要补不同路线。

当前 AI Comic 第一阶段仍以主流婚恋/共同生活为主要范围，因此先记录为 Boundary，不强行补全所有关系形式。

## 3.3 有些 External Research 是 Outcome Evidence，不是 Scene Taxonomy

例如睡眠、财务、慢性病研究能证明某类生活现实值得看，但不能单独定义全部 Scene。

所以它们作为 Evidence / Coverage Source，不机械照搬为分类。

# 4. 对 Content Map 的修正

原：

~~~text
生活场景
= 人生阶段 × 共同生活领域 × 事件 / 压力
~~~

当前 Research-only 修正版：

~~~text
生活场景
= 人生 / 关系阶段
× 共同生活领域
× Trigger / Transition / Stressor
× Task / Resource Reallocation
→ Concrete Scene
+ Pattern / Time Dynamics
~~~

Decision / Interaction 是场景进入故事后的作用层，不要求每个 Topic 都显式显示。

这版要等 Need/Fit 和 Combination Space 验证后再决定是否 Promotion。
