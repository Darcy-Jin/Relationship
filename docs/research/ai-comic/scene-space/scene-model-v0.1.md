## 1. Scene 不是一个“事件名”

第一轮 364 条 Raw Item 显示，一个可用于 Relationship 内容的真实场景至少要分开看：

~~~text
什么时候
×
生活的哪一块
×
发生了什么变化 / 压力
×
需要重新分配什么任务 / 资源
×
两个人现场怎么互动 / 决定
×
这件事是一次，还是反复发生
~~~

因此不再把“恋爱 / 生孩子 / 家务 / 吵架 / 生病”平铺成一个 Scene List。

当前保留 7 个 Scene View。

---

# 2. S1｜Life / Relationship Stage

回答：

> **这件事发生在两个人关系和人生的什么阶段？**

第一层：

~~~text
S1.1 认识 / 相亲
S1.2 恋爱 / 磨合
S1.3 稳定交往
S1.4 同居 / 婚前
S1.5 结婚 / 建立家庭
S1.6 备孕 / 怀孕 / 生育
S1.7 婴幼儿照护
S1.8 孩子成长 / 教育
S1.9 中年：事业 + 孩子 + 父母
S1.10 退休 / 老年 / 长期照护
~~~

阶段不是确定路径，也不是每对伴侣都必须经过。

它的作用是：

> 同一个 Person Feature 在不同阶段，现实含义会变。

# 3. S2｜Shared-life Domain

回答：

> **这段共同生活具体在处理哪一类现实？**

第一层：

~~~text
S2.1 日常作息 / 生活管理
S2.2 工作 / 事业 / 学习
S2.3 钱 / 财务
S2.4 房 / 居住 / 地点
S2.5 家务 / 家庭劳动
S2.6 孩子 / 生育 / 教育
S2.7 双方父母 / 原生家庭
S2.8 社交 / 朋友 / 个人空间
S2.9 兴趣 / 休闲 / 旅行
S2.10 性 / 身体亲密
S2.11 健康 / 疾病 / 照护
S2.12 价值 / 人生方向
~~~

这和当前 Relationship 的 Event Domains 基本一致，但这里更完整地服务内容研究。

# 4. S3｜Trigger / Transition / Stressor

回答：

> **什么变化把平时隐藏的问题带到了台前？**

第一层：

~~~text
S3.1 时间压力
S3.2 工作变化
S3.3 收入 / 财务变化
S3.4 居住 / 城市变化
S3.5 生育 / 育儿转折
S3.6 父母 / 家庭责任变化
S3.7 健康 / 疾病 / 意外
S3.8 社交 / 边界事件
S3.9 性 / 亲密变化
S3.10 长期累积 / 反复小问题
~~~

典型 Raw Term：

- 加班、出差、晋升、失业、创业；
- 缺钱、负债、大额支出；
- 买房、搬家、异地；
- 怀孕、生孩子、孩子生病；
- 父母住院、照护；
- 自己生病、慢性病、残障；
- 朋友临时加入、边界冲突；
- 同一问题第三次、第五次出现。

外部研究也反复说明：

> 关系变化往往不是“某个标签突然变坏”，而是转折和压力重新分配了时间、任务、角色和情绪容量。

---

# 5. S4｜Task / Resource Reallocation

回答：

> **这个场景真正逼两个人重新分配什么？**

第一层：

~~~text
S4.1 时间
S4.2 钱
S4.3 精力 / 注意力
S4.4 家务
S4.5 育儿
S4.6 照护
S4.7 工作机会 / 职业牺牲
S4.8 空间 / 居住
S4.9 情绪支持
S4.10 决策权 / Mental Load
~~~

这个 View 很重要，因为很多所谓“场景冲突”底层其实是：

> **有限资源重新分配。**

例如“生孩子”不是一个单独结果，而会同时改变：

- 睡眠；
- 时间；
- 家务；
- 育儿；
- 工作；
- 性；
- 钱；
- 父母介入；
- 公平感。

---

# 6. S5｜Concrete Scene / Interaction

回答：

> **真正画出来时，眼前发生了什么？**

这是 Content 最终需要落到的一层。

例如：

~~~text
“事业与家庭冲突”
↓
不能直接画

“孩子半夜发烧，明早一方要做重要汇报”
↓
可以画
~~~

当前已有场景原型：

- 普通周末；
- 临时加班；
- 约会被工作电话打断；
- 第三次临时取消计划；
- 同居后家务累积；
- 朋友临时加入；
- 预算怎么分；
- 重大事业机会；
- 玩家 / 伴侣生病；
- 父母突然住院；
- 谈性需求；
- 一方连续睡不好；
- 慢性病后长期照护。

---

# 7. S6｜Decision / Action

回答：

> **场景里两个人真正要做什么选择？**

它不是 Scene 本身，但决定 Scene 有没有作用。

第一层：

~~~text
S6.1 接受 / 配合
S6.2 协商条件
S6.3 表达需要
S6.4 设边界
S6.5 要求改变
S6.6 各自处理
S6.7 承担 / 分工
S6.8 拒绝 / 坚持
S6.9 支持 / 牺牲
S6.10 继续 / 犹豫 / 离开
~~~

AI Comic 不一定要求读者点击，但好的内容单元往往让读者自然想到：

> **如果是我，我会怎么办？**

---

# 8. S7｜Pattern / Time Dynamics

回答：

> **同一件事在时间里是什么形状？**

至少区分：

~~~text
一次偶发
反复发生
频率增加
严重程度增加
持续时间变长
已经表达过仍不调整
发生后能修复
发生后持续积累
~~~

这能避免内容写成：

> “他有一次忘记洗碗，所以他没责任感。”

真正重要的往往是：

> **一件小事反复出现以后形成了什么模式。**

---

# 9. 一个完整 Scene 的生成式

当前候选：

~~~text
Life / Relationship Stage
×
Shared-life Domain
×
Trigger / Stressor
×
Task / Resource Reallocation
↓
Concrete Scene
↓
Decision / Interaction
↓
Pattern over Time
~~~

例如：

~~~text
育儿期
×
工作 + 孩子
×
孩子突然发烧 + 明天重要汇报
×
谁请假 / 谁熬夜 / 谁通知家人
↓
凌晨两点孩子高烧，两个人站在客厅讨论第二天怎么办
↓
一方直接请假 / 协商轮换 / 默认另一方承担 / 争执
↓
这是第一次，还是过去半年一直如此？
~~~

# 10. Scene Space 与其他空间边界

## Person Feature

回答：

> **这个人通常是什么样、怎样分配资源、怎样反应。**

## Scene

回答：

> **在什么现实约束下，什么事情正在发生。**

## Relationship Process

回答：

> **两个人在这个场景里怎样回应、协商、冲突、修复。**

## Need / Fit

回答：

> **为什么同一个结果对不同人意义不同。**

四者要 Mapping，不要互相复制。

# 11. 当前用法

Scene 研究结束以后，内容不再从“想到一个冲突场景”开始。

而是可以从：

~~~text
某个人物特点
↓
选择最能让它进入生活的 Stage / Domain / Trigger
↓
补 Task / Resource Reallocation
↓
压成一个可画的 Concrete Scene
↓
再与 Need / Fit 组合
~~~

当前模型仍为 Research-only，等待 Need/Fit Space 和 Combination Space 一起验证。
