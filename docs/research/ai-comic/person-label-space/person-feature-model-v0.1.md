# 人物特征空间候选模型 v0.1

> 状态：Research-only / Candidate Model  
> 上游：`../12-person-label-feature-space-research.md`  
> 原始语料：`raw-corpus-v0.1.csv`  
> 映射：`raw-to-view-mapping-v0.1.csv`

## 1. 先记住：不是一棵标签树

当前证据更支持：

~~~text
现实中的一个人
↕
多个互补 View
~~~

不同 View 回答不同问题。一个 Raw Term 可以映射到多个 View；不要为了分类整齐强行只放一个地方。

当前候选 8 个 View：

~~~text
A｜Profile / Reality Facts
B｜Social Identity / Context
C｜Perceived Traits / Lay Labels
D｜Values / Goals / Priorities
E｜Capabilities / Regulation
F｜Lifestyle / Resource Allocation
G｜Relationship Process
H｜Compatibility / Needs / Fit
~~~

其中 H 更接近两个人之间的 Fit，不是单纯 Person Feature；G 也有一部分是关系共同产生的过程。

---

# 2. A｜Profile / Reality Facts

回答：

> **现实中直接能知道、能展示、能筛选什么？**

第一层：

~~~text
A1 身体 / 外在
A2 人口与生命阶段
A3 教育 / 文化资本
A4 工作 / 职业
A5 收入 / 经济
A6 居住 / 资产
A7 婚史 / 生育状态
A8 健康与基础生活事实
~~~

例子：

- 身高、体型、外貌；
- 年龄；
- 学历、毕业院校；
- 职业、公司类型；
- 收入；
- 房、车；
- 婚姻状况、是否有孩子；
- 吸烟饮酒、身体健康。

注意：

> **事实可以筛人，但不能直接推出共同生活质量。**

---

# 3. B｜Social Identity / Context

回答：

> **这个人当前处在什么社会、家庭和人生条件里？**

第一层：

~~~text
B1 地域 / 流动
B2 家庭背景 / 家庭结构
B3 社会与职业环境
B4 人生经历
B5 当前约束 / 压力
~~~

例子：

- 籍贯、户口、城乡出身、城市；
- 家庭背景；
- 原生家庭；
- 工作经历、创业经历、过去关系；
- 失业、债务、父母生病、带孩子、当前压力。

注意：

> Context 会改变一个人“现在能做到什么”，但不能自动变成人格结论。

---

# 4. C｜Perceived Traits / Lay Labels

回答：

> **普通人第一眼会怎么概括这个人？**

第一层先保持用户语言：

~~~text
C1 品格 / 道德印象
C2 情绪 / 气质
C3 主动性 / 控制感
C4 社交 / 表达
C5 成熟 / 稳重
C6 个性 / 风格
~~~

原始词包括：

- 善良、真诚、诚实；
- 冷静、稳重、情绪稳定、敏感；
- 强势、随和、完美主义；
- 开朗、话唠、文静、羞涩；
- 成熟稳重、有气质、个性。

规则：

> **C View 只保存“人们怎么说”，不直接把这些词当行为机制。**

下一步必须映射到 D / E / F / G 或具体场景，才能进入正式内容推理。

---

# 5. D｜Values / Goals / Priorities

回答：

> **这个人真正把什么排在前面？**

第一层：

~~~text
D1 事业 / 成长
D2 家庭 / 婚育
D3 钱 / 安全
D4 自由 / 自主
D5 忠诚 / 道德
D6 人生观 / 三观
~~~

例子：

- 事业和家庭排序；
- 是否要孩子；
- 对钱、安全、自由、忠诚的理解；
- 三观；
- 成长需要。

注意：

> “上进”“顾家”“孝顺”等用户标签，经常混合了 D View 和实际行为，不能只留在 C View。

---

# 6. E｜Capabilities / Regulation

回答：

> **他实际有能力把什么事情处理好？**

第一层：

~~~text
E1 工作 / 赚钱能力
E2 思考 / 决策能力
E3 自我控制 / 情绪调节
E4 沟通 / 共情
E5 问题解决
E6 学习 / 修正
~~~

Raw Corpus 当前出现：

- 工作能力；
- 逻辑力；
- 决策能力；
- 自控力；
- 共情力；
- 延迟满足；
- 会解决问题。

注意：

> 能力和“愿不愿意”不同；能力也不等于在所有场景都会使用。

---

# 7. F｜Lifestyle / Resource Allocation

回答：

> **他每天怎样用时间、钱、精力、注意力和空间？**

第一层：

~~~text
F1 工作投入
F2 时间 / 陪伴
F3 钱 / 消费
F4 社交
F5 健康 / 运动
F6 作息 / 日常
F7 兴趣 / 休闲
F8 计划性 / 可预测性
~~~

例子：

- 工作忙、事业投入；
- 日常可用时间；
- 消费 / 储蓄；
- 社交能量；
- 运动、饮食；
- 作息、整洁；
- 旅行、游戏、兴趣；
- 计划性、可预测性。

这是最容易直接变成漫画生活场景的一层。

---

# 8. G｜Relationship Process

回答：

> **两个人进入关系以后，互动怎样运行？**

第一层：

~~~text
G1 回应
G2 可靠 / 承担
G3 公平 / 合作
G4 尊重 / 边界
G5 冲突
G6 修复
G7 支持 / 照护
G8 承诺 / 忠诚执行
~~~

Raw Corpus 当前出现：

- 回应、可靠、公平、边界；
- 冲突、修复；
- 有责任心、愿意付出；
- 不冷暴力、不翻旧账；
- 尊重女性、家庭边界。

注意：

> G View 不能全部写成“这个人的固定属性”。很多关系过程取决于 Person × Partner × Scene。

---

# 9. H｜Compatibility / Needs / Fit

回答：

> **为什么同一个人对甲很合适，对乙却很难受？**

当前第一层只保留候选：

~~~text
H1 陪伴 / 连接
H2 自主 / 空间
H3 情绪交流 / 情绪价值
H4 生活节奏
H5 价值 / 人生方向
H6 安全 / 资源期待
H7 亲密 / 性
H8 家庭与边界匹配
~~~

当前 Raw Corpus 对 H 的直接覆盖很弱。

这不是说明 H 不重要，而是说明：

> **婚恋平台字段和传统“择偶标准”资料天然更擅长收集单人属性，不擅长描述两个人之间的 Fit。**

所以 H 必须单独做 Research，不能从 Person Label Corpus 硬推出来。

# 10. 典型跨 View 词

## 情绪稳定

可能同时涉及：

~~~text
C｜别人感觉他很稳
+
E｜自我调节能力
+
G｜冲突时是否失控 / 是否能回应
~~~

因此不能写：

> 情绪稳定 = 会共情 = 会沟通。

## 孝顺

可能同时涉及：

~~~text
C｜社会评价词
+
D｜家庭价值优先级
+
F｜时间 / 钱向父母投入
+
G｜父母与伴侣冲突时的边界处理
~~~

## 上进

可能同时涉及：

~~~text
C｜用户评价词
+
D｜成长 / 事业目标
+
E｜工作和学习能力
+
F｜实际投入时间精力
~~~

## 顾家

可能同时涉及：

~~~text
C｜用户评价词
+
D｜家庭优先级
+
F｜家庭时间 / 资源投入
+
G｜家务、育儿、照护中的责任与公平
~~~

这些词特别适合做 Relationship 内容，因为：

> **用户以为自己理解了这个词，但真正进入生活时才发现它里面混了很多不同东西。**

---

# 11. 当前模型怎么用

不是：

~~~text
Raw Term
→ 找一个分类
→ 结束
~~~

而是：

~~~text
Raw Term
↓
保留用户原词
↓
判断它涉及哪些 View
↓
拆成可观察事实 / 行为 / 机制
↓
放进生活场景
↓
和伴侣 Need / Fit 组合
↓
形成 Topic
~~~

当前模型继续等待 Coverage / Conflict、真实 Topic 和新 Corpus 验证。
